diff(1), rebuilt · Myers 1986

−diff+tool

Paste two versions of a text. The tool finds a shortest edit script with Eugene Myers' O(ND) greedy algorithm, shows it side by side or as a unified patch, highlights the words that changed inside each line, and draws the edit graph so you can watch the D-paths reach across it.

Edit graph

      
A runs left to right and B top to bottom. A step right deletes a line of A, a step down inserts a line of B, and a free diagonal (dashed) is a line they share. Each D-path is the furthest point reachable on its diagonal k = x − y with exactly D edits; Myers stops at the first D that reaches the corner.

How it works

      
    
        
  1. Each line becomes a comparison key: trimmed of all whitespace if you ignore whitespace, lower-cased if you ignore case. A last line with no newline gets a marker, so b and b⏎ differ, as in GNU diff and git.
    2. 
        
  2. For D = 0, 1, 2 … the array V[k] stores the furthest x reached on diagonal k. From V[k−1]+1 (right) or V[k+1] (down) the path follows the diagonal "snake" as far as the lines match.
    3. 
        
  3. The first D that reaches (N, M) is the edit distance; a copy of V per round lets the path be walked back from the corner into the edit script.
    4. 
        
  4. Unified hunks keep n lines of context and merge when two changes are within 2n lines. A hunk header is @@ -start,count +start,count @@; a count of 1 is left out, and an empty side starts at the line before it.
    5. 
        
  5. Each deleted line is paired with the inserted line in the same position of its block, and the pair is diffed again on word tokens for the highlights.
    6. 
      

      
Up to 1,500 lines a side. Myers' refinement (the linear-space middle snake) isn't needed at that size, so this keeps the simpler O((N+M)·D) time, O(D²) space form.
