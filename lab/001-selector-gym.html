      Why role-based locators win

      • They read like the user. getByRole('button', {name: 'Place order'}) is how a person (and a screen reader) finds that control. If it breaks, the UI probably broke for real users too.
      • They survive refactors. Class names like .css-9f3k1 are build artefacts; they change when someone swaps a CSS-in-JS library. Roles and labels change only when the product changes.
      • They test accessibility for free. An unlabeled input simply can't be found by getByLabel — your test fails exactly where an a11y audit would.
      • Test IDs are the escape hatch. Stable and explicit, but invisible to users. Reach for them when no accessible handle exists (a price readout, a canvas).
