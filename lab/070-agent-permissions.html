Precedence (the semantics used here)

  1. Collect every rule that matches the call.
  2. Deny beats ask beats allow, whatever order the rules are in. One matching deny is enough.
  3. No match at all: use the “when nothing matches” setting.
  4. For a Bash command joined with &&, ||, ; or |, each part is judged separately and the strictest result wins, so an allowed prefix can't smuggle in a second command.
  5. Command substitution ($(…) or backticks) is never auto-run: at best it asks.

Patterns

  • Read(src/**): paths use globs. ** spans folders, * stays inside one, ? is one character. **/.env also matches .env at the root.
  • Paths outside the project (../, /, ~) never match a project-relative pattern.
  • Bash(npm test:*): prefix match on whole words (npm test, npm test -- --ci, but not npm testify). Without :* the command must match exactly.
  • WebFetch(domain:example.com): that host and its subdomains. A bare tool name matches every call of that tool.

Probe calls behind the meters

Risk adds up what the agent could do without asking (asking counts a quarter). Friction counts routine calls that stop to ask, or are blocked.

    This is a design sandbox with its own generic rule language. It isn't the exact syntax or behaviour of any particular agent product, so check your tool's documentation before copying rules across. Nothing on this page executes anything: tool calls are only matched against text patterns.
