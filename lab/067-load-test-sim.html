A queueing model of Parcelhook, a fictional order-tracking service. Virtual users send a request, wait for the answer, think, and go again. Requests queue for a pool of workers. Push the users up and watch the point where extra load stops buying throughput and starts buying latency.

The knee

Each dot is a 5-second window: users on the x axis, throughput and p95 on their own scales. Past the knee the green dots flatten while the yellow ones climb.

How the model works: a closed-loop discrete-event simulation. Each virtual user sends one request, waits for a response or its timeout, then thinks for an exponentially distributed time. Requests are served first come, first served by c workers. A full queue rejects immediately (think HTTP 503). A request that times out while queued is abandoned, but one that times out mid-service keeps its worker busy until it finishes (wasted work). Percentiles use the nearest-rank method over the raw samples, never averages of averages. Randomness comes from a seeded PRNG (mulberry32), so the same seed and settings always give the same run. Try ?seed= in the URL.
