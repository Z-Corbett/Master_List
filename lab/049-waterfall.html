    How the simulation works (and what it leaves out)
    • Bandwidth is shared between all downloads in flight. With HTTP/2 each origin gets one connection and shares are weighted by priority (Highest 8 · High 4 · Medium 2 · Low 1); with HTTP/1.1 each origin may open up to six connections, each paying its own TCP and TLS round trips, and shares are equal.
    • A new origin costs one round trip for DNS, one for TCP and one for TLS 1.3. Time to first byte is one round trip plus the server's think time.
    • Resources in the HTML are found when the document finishes arriving. Preload hints are found as soon as the response headers arrive. The web font is otherwise only found when the page is first styled, because the browser needs CSS and layout to know the text uses it.
    • Synchronous scripts wait for the stylesheet, then block the parser and first paint. Deferred scripts run in order after parsing; async scripts run whenever they arrive. Text uses font-display: swap, so the font never blocks paint.
    • LCP is the hero image: it paints at the later of first paint and the image arriving (plus a short decode). Lazy-loading applies only to the four below-the-fold product photos, which are then not requested during the initial load.
    • Timing budgets use the widely quoted “good” thresholds: FCP 1.8 s and LCP 2.5 s.
