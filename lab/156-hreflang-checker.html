hreflang Checker

Paste the hreflang annotations for a set of pages, as HTML <link> tags or as a sitemap with xhtml:link, and check them the way Google's documentation describes: valid codes, return links, self-references, x-default, duplicate codes and canonical conflicts. Nothing is fetched. It only reads what you paste.

    What it checks, and where each rule comes from

    • Language: ISO 639-1. The first code must be a two-letter ISO 639-1 language, such as en, de or ja (not jp, which is a country). Three-letter codes aren't supported. The check uses an embedded copy of all 183 ISO 639-1 codes.
    • Region: ISO 3166-1 alpha-2, optional. A second code can give the country: en-GB, not en-UK. UK, EU and UN are reserved rather than assigned, and Google says it ignores that part of the annotation. A region can't be used on its own, because Google doesn't derive a language from a country. The check uses an embedded copy of all 249 assigned ISO 3166-1 alpha-2 codes.
    • Script: ISO 15924, optional. Google also accepts a script subtag, as in zh-Hant or zh-Hant-TW. This tool knows the common scripts, and it warns rather than errs on any other four-letter subtag.
    • UN M.49 regions such as es-419: not supported. es-419 is valid BCP 47 (Spanish for Latin America and the Caribbean), but Google's hreflang documentation names it as unsupported: only ISO 639-1 languages and ISO 3166-1 alpha-2 regions are. So this tool reports it as an error. Use country codes (es-MX, es-AR, …), or plain es with x-default.
    • Return links. If page X lists page Y, page Y must list page X. Otherwise the pair may be ignored.
    • Self-reference. Each language version must list itself as well as all the other versions.
    • x-default. Optional, but recommended: it names the page for users whose language matches no version, such as a language picker. A missing x-default is a warning.
    • Duplicate codes. One page can't send the same language-region pair to two different URLs. The same annotation repeated is only a warning.
    • Canonical conflicts. Every hreflang target should be the canonical URL of its version. A page whose rel="canonical" points elsewhere is telling Google to index a different URL, which contradicts being an hreflang alternate.
    • Fully qualified URLs. Alternate URLs must include the protocol and host. A relative href is an error.

    Sources: Google Search Central, "Tell Google about localized versions of your page" (developers.google.com/search/docs/specialty/international/localized-versions). It says: "Only language codes listed in ISO 639-1 and region codes listed in ISO 3166-1 Alpha 2 are supported; other codes that aren't listed in those standards, such as es-419, aren't supported." It also covers return links, self-references, x-default, the sitemap xhtml:link form, and the en-UK mistake. On canonicals, Google Search Central, "How to specify a canonical URL": "If you're using hreflang elements, make sure to specify a canonical page in the same language". Code lists: ISO 639-1, ISO 3166-1 (officially assigned alpha-2 codes), and ISO 15924.
