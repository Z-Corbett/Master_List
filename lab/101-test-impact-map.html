      How the selection works

      1. Reverse the graph. Each module lists what it imports. Flipping every edge gives, for each module, the modules that import it.

      2. Walk it breadth-first. Start from the changed files and follow the reversed edges until nothing new turns up. Everything reached is affected: its behaviour could change even though its own code didn't. The walk records who reached whom, so each affected module can show the chain back to a changed file.

      3. Select tests. Each test is mapped to the modules it targets directly. A test runs if any of those modules is affected. Tests with no coverage data run unless you switch that off, and smoke tests run if the toggle is on. A change to a global file such as package-lock.json can change anything, so it runs the full suite.

      What this can't see. Dynamic imports, config read at runtime, CSS, feature flags flipped on a server, and anything outside the import graph. That's why the always-run buckets exist: they trade some of the saving for cover against the graph being wrong.
