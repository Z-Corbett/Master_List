Prompt Cache Planner

A prefix cache can only reuse the prompt up to the first token that differs from last turn. Everything after that point is processed again, however stable it is. Put the segments in order, set how big each one is and how often it changes, and watch what twenty turns cost.

    Model: turn 1 starts with an empty cache. On later turns the cache holds last turn's prompt, and the hit runs until the first segment that changed. Assumed: nothing expires within the 20 turns, there is no minimum cacheable length, and the uncached tail is written to the cache each turn. Real conversation history is usually append-only, so its older part can stay cached; here it is treated as one segment that changes, which is the pessimistic case.
