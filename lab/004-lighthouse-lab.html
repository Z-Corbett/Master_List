How the model works

  • Network: 4 Mbps (500 KB/s) with 120 ms round trips. Downloads that run in parallel share bandwidth, so eager below-the-fold images and the chat widget slow the hero down.
  • FCP = TTFB + HTML + render-blocking CSS/JS (download, then execute) + invisible-text time while the font loads.
  • LCP = when the hero is discovered (by the preload scanner, or only after blocking scripts) + its download at its share of bandwidth + main-thread render delay.
  • TBT sums each long task's time over 50 ms: bundle execution, hydration, the chat widget. INP is roughly handler + paint + input delay caused by those same tasks.
  • CLS adds shift scores from images without dimensions, the late promo banner and font swapping.
  • Performance = 10% FCP + 10% SI + 25% LCP + 30% TBT + 25% CLS, each scored on a log-normal curve (mobile control points). The other categories are weighted pass/fail audits.
