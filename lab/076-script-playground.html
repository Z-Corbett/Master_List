Bitcoin decides whether coins can move by running two small programs back to back: the spender's unlocking script, then the coin's locking script. Step through them one opcode at a time and watch the stack. The hashes are real; the signatures are not.

Scripts edit freely

OP_CHECKSIG is SIMULATED. There is no ECDSA here. Keys and signatures are stand-ins: a "pubkey" is 02 ‖ SHA256("pubkey:" ‖ name), and a "signature" is valid when it equals 30 ‖ SHA256("sim-sig:" ‖ pubkey). Write them as <pub:alice> and <sig:alice>. Real signatures commit to the spending transaction; these do not.

    Opcodes in this subset

    OpcodeEffect
    <hex> · 0x.. · "text" · 17Push data. Small numbers use OP_0 … OP_16 and OP_1NEGATE, larger ones minimal script-number encoding.
    OP_DUP / OP_DROP / OP_SWAPCopy the top item / discard it / swap the top two.
    OP_ADD / OP_SUBPop two script numbers (4 bytes at most) and push a+b or a−b.
    OP_EQUALPop two items and push 1 if the bytes match, otherwise an empty array (false).
    OP_VERIFY / OP_EQUALVERIFYFail the script unless the top is true (OP_EQUALVERIFY runs OP_EQUAL first).
    OP_IF / OP_ELSE / OP_ENDIFBranch on the popped top item; skipped opcodes are struck through on the tape.
    OP_SHA256 / OP_HASH160Replace the top with SHA-256(x), or RIPEMD-160(SHA-256(x)).
    OP_CHECKSIGSimulated: pop pubkey and signature and push 1 if the stand-in signature matches.

    A script succeeds when nothing fails and the top item left at the end is true (not empty, not all zero bytes). As in Bitcoin, an IF that opens in the unlocking script cannot close in the locking script.
